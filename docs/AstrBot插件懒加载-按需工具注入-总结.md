# 插件懒加载 · 按需工具注入 总结

> 核心思想：工具照常加载和注册，但只有被激活的工具，其完整 JSON Schema 才会进入当轮 LLM 请求。

## 1. 核心目标与本质

- 不是真正卸载插件，也不是让插件不加载。
- 采用全量注册、按需注入：工具在机器人内部存在，但对模型暂时不可见。
- 只有被激活的工具，其完整 Schema 才会进入当轮请求。
- 未激活的工具不占用提示词预算，模型也看不到。

### 省什么，不省什么

- 省：提示词 token、上下文窗口、模型 prefill 成本。
- 不省：工具执行算力。
- 增加：本地检索、索引、状态管理等机器人侧开销。
- 适用：工具数量多、描述长、会话长、上下文紧张。
- 不适用：只有十几个工具时，收益可能不足以覆盖复杂度。

## 2. AstrBot 插件格式要点

- 插件入口通常是 `main.py`，插件类必须继承 `Star`。
- 插件目录必须有 `metadata.yaml`，AstrBot 依赖它识别插件。
- 可选：`_conf_schema.json`、`requirements.txt`、`logo.png`。
- 事件处理器写在插件类内部，前两个参数固定为 `self` 和 `event`。
- 通过 `filter` 下的装饰器注册命令、权限和事件类型。
- 插件卸载或禁用时可实现 `terminate` 做清理。
- `Context` 是插件与 AstrBot 核心交互的主要入口。

懒加载插件不改变 AstrBot 底层机制，而是在标准插件结构上扩展出自己的注册、检索、激活、注入和执行体系。

## 3. 插件总结构

### 加载期

- 采集工具元数据。
- 建立全量注册表。
- 建立检索索引。

### 运行期

- 每轮对话前预检索。
- 维护会话激活表。
- 动态拼接要注入的 Schema。
- 统一校验和执行工具。

### 分层职责

- 入口层：初始化组件，把预检索、Schema 注入挂到生命周期钩子。
- 核心层：注册表、索引、检索器、激活管理、注入器、执行器、装饰器。
- 元工具层：搜索工具、激活工具、取消激活工具。
- 配置层：检索数量、过期轮次、过期时间、检索模式等。
- 子插件层：管理和加载插件内部的工具包。

## 4. 加载阶段原理

- 所有标记懒加载装饰器的工具会自动采集元数据。
- 元数据包括：工具名、描述、参数签名、标签、示例、过期配置等。
- 元数据存入全量注册表，并用于构建检索索引。
- 此阶段不做真正的模块级懒加载。
- 所有工具代码正常加载、正常注册，与普通插件没有区别。
- 区别只在于：注册表中工具不会自动注入 LLM 请求。

## 5. 每轮对话运行原理

1. 本地预检索：用用户输入和最近上下文，在索引中召回候选工具；MVP 可用关键词和标签匹配，后续可升级 BM25 加向量混合检索。
2. 激活表管理：把命中工具写入当前会话激活表；每轮开始做轮次衰减和时间过期清理。
3. Schema 注入：固定加入搜索、激活、取消激活三个元工具，再加上所有已激活工具的完整 JSON Schema。
4. LLM 正常调用：模型看到的就是注入后的工具列表，与普通 function calling 一致。
5. 统一执行器：校验是否在激活表、校验参数、校验权限、设置超时、执行原 handler、裁剪返回结果。

## 6. 元工具兜底

- 预检索可能漏掉工具，因此固定向模型暴露三个元工具：
  - 搜索工具
  - 激活工具
  - 取消激活工具
- 预检索失败时，模型可以主动搜索、激活，再调用工具。
- 代价是多一轮模型调用。
- 设计上优先让预检索自动激活，元工具作为低置信场景兜底。

## 7. 机器人隔离

- 解决"哪个 bot"的问题。
- 激活表、工具索引、配置数据应按 bot 分区，互不干扰。
- 会话 key 强制包含 bot 标识。
- bot 标识可取平台适配器唯一标识，或 UMOP 格式中的 `platform_id`。
- 注册表和索引可全局共享；激活表必须按 bot 分区。
- 工具定义全局共享，但每个 bot 的会话激活状态独立。
- 配置支持按 bot 覆盖。
- 完全独立的多 bot 实例可由 AstrBot Launcher 管理，每个实例独立运行，天然隔离。

## 8. 会话隔离

- 解决"哪个对话"的问题。
- AstrBot 以 UMOP 为会话管理基本单元，在 UMOP 级别维护会话状态和配置偏好。
- 激活表以 UMOP 为粒度：群聊和私聊天然隔离。
- 群聊默认共享上下文；开启成员级隔离后，会话 key 从 `bot_id + UMOP` 扩展为 `bot_id + UMOP + user_id`。
- 跨会话记忆共享与激活隔离分离：使用统计和索引可跨会话共享，激活表仍是会话级。
- 并发安全：同一会话的多个并发请求需要会话级锁保护激活表一致性。
- 可支持 `disable_group_queue`：不同成员不共用群聊会话锁，改为按成员分别等待，但同一成员仍串行。

## 9. 插件中装插件

- 懒加载插件可以管理和加载子插件，形成内部工具生态。
- 推荐结构：主插件目录下建立 `sub_plugins/`，每个子插件是一个工具集合。
- 子插件不需要继承 `Star`，不需要 `metadata.yaml`，不需要 `_conf_schema.json`，只需提供工具定义。
- 启动时扫描、动态导入子插件，采集元数据并注入主插件注册表。
- 子插件不进入 AstrBot 全局插件管理器，不会被 AstrBot 直接加载。
- 支持运行时启用和禁用：禁用时移除工具并清理激活项，启用时重新导入注册。
- 子插件可以有独立 `requirements.txt`，依赖安装在子插件级别。
- 工具提供者可以以子插件形式分发工具包，用户只需安装一个懒加载插件。
- 安全边界：子插件与主插件同进程，代码问题会影响主插件；更强隔离可放到独立进程，通过标准输入输出或 WebSocket 通信。

## 10. 主要风险与应对

| 风险 | 应对 |
| --- | --- |
| 冷启动延迟 | 后台异步建索引、高频工具预热 |
| 误调用 | 相似度阈值、权限校验、激活校验、高风险工具二次确认 |
| 漏工具 | 低置信注入默认工具组、搜索元工具兜底 |
| Schema 漂移 | 记录版本号或哈希，重载后失效并重建索引与激活表 |
| 并发冲突 | 会话级锁、每轮使用激活表快照 |
| 提示注入 | 清洗工具描述和标签、敏感工具不参与自动激活 |

## 11. 里程碑与适用边界

### MVP

- 装饰器采集元数据。
- 关键词和标签检索。
- 会话激活表。
- 轮次和时间双过期。
- 注入已激活 Schema。
- 统一执行器。

### M2

- embedding 索引。
- BM25 加向量混合召回。
- 预检索自动激活。

### M3

- 无结果时注入默认工具组。
- 低置信时让模型搜索。
- 向量不可用时降级关键词。
- 监控指标。

### M4

- 工具分组。
- 权限体系。
- 多 bot 灰度。
- 工具市场和自动标签。

### 适用边界

适合工具数量多、描述长、会话长、上下文紧张的场景。工具越多，收益越显著；工具少时，复杂度可能不划算。

## 12. 一句话总结

工具照常注册，说明书按需注入；本地检索先激活，再把 Schema 给模型看；省的是提示词预算和上下文窗口，不是算力；机器人隔离到 bot，会话隔离到 UMOP，群成员隔离可选；子插件解决工具膨胀，让一个懒加载插件装下可扩展的工具生态。

- [ ] 是否有本地预检索和索引构建流程。
- [ ] 是否有会话级激活表及双过期机制。
- [ ] 是否固定注入搜索、激活、取消激活三个元工具。
- [ ] 是否有统一执行器做校验、权限、超时和结果裁剪。
- [ ] 激活表是否按 bot 分区。
- [ ] 会话状态是否按 UMOP 隔离。
- [ ] 群成员隔离是否可选。
- [ ] 是否处理会话并发锁。
- [ ] 子插件是否有独立加载、启用、禁用和依赖管理。
- [ ] 是否考虑 Schema 漂移、提示注入和冷启动。
- [ ] 是否按工具规模评估收益，而不是盲目引入懒加载。
